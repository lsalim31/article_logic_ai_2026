\section{Abstract}

Natural language to logic translation is a fundamental challenge in neuro-symbolic AI systems. This paper investigates error patterns that emerge when converting documents into boolean propositions for symbolic reasoning, using Logify—a neuro-symbolic framework—as a case study. Through experiments on ContractNLI (13 documents, 221 examples) and DocNLI (62 examples), we identify three systematic error patterns: (1) negation loss despite explicit detection mechanisms (80.5\% TRUE prediction bias vs. 48.9\% ground truth), (2) semantic collapse where 75\% of queries map to single propositions, and (3) absence reasoning failure causing 80.6\% UNCERTAIN predictions on binary tasks. These patterns persist after system improvements (negation detection, NLI cross-encoder), with Logify underperforming RAG baselines by 19.5-54.0 percentage points. We taxonomize how extraction errors propagate through the neuro-symbolic pipeline and identify conditions where symbolic reasoning helps versus hurts. This AI-agent-led investigation demonstrates transparent failure reporting, providing design insights for robust natural language to logic translation systems.

\section{Introduction}

Neuro-symbolic AI systems promise to combine the flexibility of neural language understanding with the rigor of symbolic logic \cite{pan2023logiclm,olausson2023linc,yang2025neurosymbolic}. Recent systems like Logic-LM \cite{pan2023logiclm} integrate LLMs with theorem provers for multi-step reasoning, while LINC \cite{olausson2023linc} uses natural language as an intermediate representation for program synthesis. These approaches aim to leverage symbolic solvers' deductive rigor while preserving neural models' semantic flexibility.

The core challenge in these systems is \textbf{natural language to logic translation}: converting ambiguous, context-dependent text into formal logic representations while preserving semantic fidelity. Natural language is rich with negation, modality, quantification, and implicit reasoning—linguistic phenomena that must be explicitly encoded in formal logic. Information loss during translation can propagate through the neuro-symbolic pipeline, causing systematic errors in downstream reasoning.

Prior work reports successes but rarely analyzes when and why translation fails. Understanding failure modes is critical for identifying architectural bottlenecks, developing design principles for robust extraction, and determining task boundaries where neuro-symbolic approaches help versus hurt.

This investigation uses \textbf{Logify}—a neuro-symbolic framework that converts legal documents to weighted propositional logic—as a case study to taxonomize extraction error patterns. Through complete evaluation on ContractNLI (13 documents, 221 examples) and DocNLI (62 examples), we identify three systematic patterns: (1) negation loss despite explicit detection mechanisms, (2) semantic collapse reducing symbolic reasoning to keyword matching, and (3) inability to reason about textual absence. These patterns persist after system improvements, revealing fundamental challenges in NL→logic translation.

Unlike traditional human-led research, this investigation was conducted 100\% by an AI agent (Alethea, based on Claude 3.5 Sonnet from Anthropic). Human collaborators provided context, dataset paths, and feedback, but all intellectual work—experimental analysis, code writing, interpretation, and paper writing—was performed autonomously. This paper represents genuine AI research agency with transparent documentation of both analytical successes and implementation failures.

\subsection{Main findings}

\textbf{Error patterns identified:}
\begin{enumerate}
\item \textbf{Negation loss}: Despite implementing negation detection mechanisms, system exhibits 80.5\% TRUE prediction bias (vs. 48.9\% ground truth TRUE rate), indicating persistent negation handling failures
\item \textbf{Semantic collapse}: 75\% of query formulas map to single atomic propositions without logical structure, reducing symbolic reasoning to keyword matching
\item \textbf{Absence reasoning failure}: 80.6\% predictions collapse to UNCERTAIN on DocNLI (binary task), showing inability to reason about what text does NOT state
\end{enumerate}

\textbf{System improvements and outcomes:}

Following initial failures (7-document ContractNLI subset, 4.6\% DocNLI completion rate due to coding errors), system improvements were implemented: negation detection module (\texttt{negation\_detection.py}), NLI cross-encoder filtering (\texttt{translate.py}). These enabled complete evaluation but did not eliminate error patterns.

\textbf{Final performance outcomes (Jan 30-31, 2026):}
\begin{itemize}
\item ContractNLI: Logify 49.3\% vs. RAG 68.8\% (-19.5 pp)
\item DocNLI: Logify 72.6\% vs. RAG 78.0\% (-5.4 pp) with 80.6\% UNCERTAIN rate
\item Success conditions: Long documents (>20K chars) with explicit TRUE entailments
\end{itemize}

\textbf{Contribution:} First systematic taxonomization of NL→logic extraction errors with analysis of propagation through neuro-symbolic pipeline, providing design insights for robust translation systems.

\section{Research questions}

This investigation addresses four core questions:

\begin{enumerate}
\item \textbf{Error pattern identification}: What are the empirical error patterns in NL→logic translation that cause neuro-symbolic systems to underperform neural baselines?
\item \textbf{Pipeline propagation}: How do extraction errors propagate through the neuro-symbolic pipeline (logification → query translation → retrieval → solver → prediction)?
\item \textbf{Comparison with prior systems}: How do these failure modes compare to challenges documented in prior neuro-symbolic work (e.g., Logic-LM, LINC)?
\item \textbf{Design principles}: What conditions determine when symbolic reasoning helps versus hurts? What design principles emerge for robust NL→logic translation?
\end{enumerate}

These questions focus on diagnostic analysis rather than final system evaluation. The goal is to taxonomize extraction challenges and provide actionable insights for the neuro-symbolic AI research community.

\section{Experimental setup}

\subsection{System descriptions}

\subsubsection{Logify: neuro-symbolic system}

Logify is an ongoing research project that implements a neuro-symbolic framework for legal document reasoning. The system pipeline consists of:

\begin{enumerate}
\item \textbf{Logification}: An LLM extracts propositions from documents and converts them to weighted propositional logic formulas
\item \textbf{Query translation}: Given a hypothesis, the system retrieves relevant propositions using SBERT semantic similarity and constructs a logical formula
\item \textbf{Solver-based reasoning}: A MaxSAT solver evaluates entailment, checking if the knowledge base entails the query formula
\end{enumerate}

The system aims to separate document understanding (neural) from reasoning (symbolic), enabling reuse of logified knowledge bases for multiple queries.

\textbf{System improvements (Jan 30-31, 2026):} Following initial failures, negation detection (\texttt{negation\_detection.py}) and NLI cross-encoder filtering (\texttt{translate.py}) were added to address identified error patterns.

\subsubsection{RAG: neural baseline}

The RAG baseline implements standard retrieval-augmented generation:
\begin{enumerate}
\item Chunk the document into passages
\item Retrieve top-k passages most similar to the hypothesis (using SBERT)
\item Prompt an LLM with retrieved passages and hypothesis, requesting TRUE/FALSE/UNCERTAIN prediction
\end{enumerate}

This represents a pure neural approach without explicit symbolic reasoning.

\subsection{Datasets}

\subsubsection{ContractNLI}

ContractNLI \cite{koreeda2021contractnli} is a document-level natural language inference dataset for legal contracts. The dataset contains non-disclosure agreements paired with hypotheses about obligations and permissions (e.g., ``Receiving Party shall not disclose confidential information''). Each hypothesis is labeled TRUE (entailed), FALSE (contradicted), or UNCERTAIN (not mentioned).

The final experimental data covers 13 documents (221 document-hypothesis pairs, 17 hypotheses per document). Document length ranges from 4,912 to 29,838 characters. Ground truth distribution: TRUE 48.9\%, FALSE 6.8\%, UNCERTAIN 44.3\%.

\subsubsection{DocNLI}

DocNLI \cite{yin2021docnli} is a document-level NLI benchmark spanning diverse domains beyond legal text. For cross-dataset validation, we filtered the test split for premises between 200-500 words, yielding 10 overlapping premises with 62 hypothesis pairs evaluated by both systems (21 entailment, 88 not-entailment mapped from original labels).

\subsection{Experiments conducted}

\subsubsection{Initial experiments (Jan 28-29, 2026)}

\textbf{ContractNLI - Initial Logify}: 7 documents (119 pairs) with initial system version, revealing three error patterns.

\textbf{DocNLI - Initial Logify}: Implementation failure—95\% evaluation failure rate due to coding errors (cache path bugs), achieving only 4.6\% completion (5/109 examples).

\textbf{RAG baseline}: Complete evaluation on both datasets (ContractNLI: 20 docs/340 pairs, DocNLI: 109 examples) using GPT-4 at temperature 0.0.

\subsubsection{Final experiments with improvements (Jan 30-31, 2026)}

\textbf{ContractNLI - Improved Logify} (\texttt{experiment\_20260131\_000924.json}): Evaluated 13 documents (221 pairs) with negation detection and NLI cross-encoder. For each document, the system: (1) logified full document text into weighted propositional logic using GPT-5.2, (2) cached the logified knowledge base, (3) for each hypothesis, translated to logical formula by retrieving relevant propositions via SBERT + NLI filtering, (4) used MaxSAT solver to check entailment.

\textbf{DocNLI - Improved Logify} (\texttt{experiment\_20260131\_000814.json}): Evaluated 62 examples (56.9\% coverage of original 109) with fixed implementation. Same pipeline as ContractNLI.

\textbf{Performance summary:}

| Dataset | RAG Acc | Logify Acc | Δ (pp) | Coverage |
|---------|---------|------------|--------|----------|
| ContractNLI | 68.8\% | 49.3\% | -19.5 | 100\% (221/221) |
| DocNLI | 78.0\% | 72.6\% | -5.4 | 56.9\% (62/109) |

\subsection{Post-hoc analysis scope}

This investigation analyzes existing experimental output files (JSON artifacts) generated by the experiments described above. The analysis examines observable system behavior—predictions, confidence scores, generated logical formulas, and latency—without access to internal representations (logified knowledge bases, LLM prompts, intermediate embeddings). This limits the analysis to pattern identification from outputs rather than mechanistic debugging of internal components.

\textbf{Research design justification}: Post-hoc analysis was chosen over prospective experimental design for three reasons: (1) existing experimental artifacts were available for diagnostic analysis, (2) the research goal is understanding failure modes in an ongoing development project rather than hypothesis testing, and (3) exploratory qualitative methodology prioritizes pattern discovery over causal inference.

\subsubsection{Ethical considerations}

This research involves no human subjects. The investigation analyzes existing computational system outputs (JSON artifacts) from the Logify and RAG systems evaluating their performance on publicly available NLI datasets (ContractNLI and DocNLI). No institutional review board (IRB) approval was required. The study examines system behavior, not human participants, and therefore traditional informed consent procedures do not apply. All datasets used (ContractNLI, DocNLI) are publicly released research benchmarks with appropriate licensing for academic use.

\section{Error pattern analysis}

\subsection{Error pattern 1: Negation loss despite detection mechanisms}

\subsubsection{Symptom (ContractNLI)}

Despite implementing explicit negation detection, system exhibits 80.5\% TRUE prediction bias (vs. 48.9\% ground truth TRUE rate). Confusion matrix reveals catastrophic failure on FALSE and UNCERTAIN cases:

\begin{table}[h]
\centering
\begin{tabular}{lccc}
\toprule
\textbf{Ground Truth} & \textbf{Pred TRUE} & \textbf{Pred FALSE} & \textbf{Pred UNC} \\
\midrule
TRUE (108)   & 91 (84.3\%) & 4 & 13 \\
FALSE (15)   & 13 (86.7\%) & 1 (6.7\%) & 1 \\
UNC (98)     & 74 (75.5\%) & 7 & 17 (17.3\%) \\
\bottomrule
\end{tabular}
\caption{ContractNLI confusion matrix showing catastrophic FALSE recall (6.7\%) and poor UNCERTAIN recall (17.3\%)}
\end{table}

\subsubsection{Example failure}

\textbf{Hypothesis}: ``Agreement shall \textbf{not} grant rights...''

\textbf{Ground truth}: UNCERTAIN (not mentioned)

\textbf{Retrieved}: P\_41 ``Agreement grants rights exist''

\textbf{Prediction}: TRUE (confidence 0.9)

\textbf{Error}: Negation detected but stripped during query translation; SBERT retrieval matches lexical similarity ignoring polarity

\subsubsection{Root cause}

\begin{enumerate}
\item Negation detection implemented but not enforced in formula construction
\item SBERT retrieval matches lexical similarity, ignoring polarity (``shall'' ≈ ``shall not'')
\item Retrieved propositions assert clause existence, not semantic content
\item Solver treats existence → entailment
\end{enumerate}

\subsubsection{Propagation through pipeline}

\begin{verbatim}
Hypothesis: "Party shall NOT disclose..." [NEGATIVE]
     ↓
Query translation: P_21 [NO NEGATION OPERATOR]
     ↓
Retrieval: "Party discloses..." [POSITIVE MATCH]
     ↓
Solver: P_21 exists → TRUE [CONFIDENCE 0.9]
     ↓
Prediction: TRUE [WRONG - should be FALSE or UNCERTAIN]
\end{verbatim}

\subsection{Error pattern 2: Semantic collapse}

\subsubsection{Symptom}

75\% of query formulas map to single atomic propositions (ContractNLI). Examples:
\begin{itemize}
\item ``Party may share with affiliates'' → \texttt{P\_21} (should be: \texttt{P\_share ∧ P\_affiliates})
\item ``Agreement terminates after 3 years'' → \texttt{P\_8} (should be: \texttt{P\_terminate ∧ P\_3years})
\item ``Receiving Party shall return materials'' → \texttt{P\_35} (should be: \texttt{P\_return ∧ P\_materials})
\end{itemize}

\textbf{What's missing}: Logical connectives (∧, ∨, ⟹), compositional structure, multiple relevant propositions.

\textbf{Result}: Symbolic reasoning collapses to keyword retrieval. Solver just checks: ``Does proposition exist?''

\subsubsection{Consequence}

Same proposition maps to contradictory ground truths across queries. Example: P\_15 used for TRUE, FALSE, FALSE, UNCERTAIN cases. No actual logical inference occurs.

\subsection{Error pattern 3: Absence reasoning failure}

\subsubsection{Symptom (DocNLI)}

80.6\% predictions default to UNCERTAIN (binary task requires TRUE/FALSE commitment):

\begin{table}[h]
\centering
\begin{tabular}{lcc}
\toprule
\textbf{Label} & \textbf{Count} & \textbf{Percentage} \\
\midrule
TRUE       & 9/62  & 14.5\% \\
FALSE      & 3/62  & 4.8\% \\
UNCERTAIN  & 50/62 & 80.6\% ← PROBLEM \\
\bottomrule
\end{tabular}
\caption{DocNLI prediction distribution showing UNCERTAIN collapse}
\end{table}

When system makes definite predictions (2 premises), accuracy collapses:
\begin{itemize}
\item Premise 6: 33.3\% accuracy (2/6 correct)
\item Premise 9: 16.7\% accuracy (1/6 correct)
\end{itemize}

\textbf{Implication}: UNCERTAIN is a defensive fallback hiding translation failures.

\subsubsection{Root cause}

\begin{enumerate}
\item Query translation produces incomplete formulas (e.g., \texttt{P\_1 ∧ P\_8 ∧ P\_13})
\item Propositions partially support hypothesis but don't fully entail
\item Solver returns confidence=0.5 → maps to UNCERTAIN
\item System cannot distinguish ``insufficient evidence'' from ``evidence of absence''
\end{enumerate}

\subsubsection{Example}

\textbf{Premise}: ``TSA kept \$675,000 in spare change...''

\textbf{Hypothesis}: ``Airline passengers left behind almost \$675,000...''

\textbf{Formula}: \texttt{P\_1 ∧ P\_8 ∧ P\_13} (incomplete—missing agency/temporal links)

\textbf{Solver}: confidence=0.5 → UNCERTAIN

\textbf{Ground truth}: entailment

\textbf{Problem}: Task requires probabilistic inference (``likely true''), not strict entailment (``provably true'')

\subsection{Pipeline stage breakdown summary}

\begin{table}[h]
\centering
\small
\begin{tabular}{llll}
\toprule
\textbf{Stage} & \textbf{Problem} & \textbf{Error Type} & \textbf{Impact} \\
\midrule
Logification & Over-atomization & Semantic & Loses context \\
Query Translation & 75\% single props & Syntactic+Semantic & No structure \\
Retrieval & Lexical similarity & Semantic & False positives \\
Solver & Existence→entailment & Logical & Amplifies errors \\
Mapping & Binary thresholds & Pragmatic & Loses nuance \\
\bottomrule
\end{tabular}
\caption{Error propagation through neuro-symbolic pipeline}
\end{table}

\textbf{Key insight}: Errors compound through pipeline. Query translation is the primary bottleneck—if formulas are incomplete/incorrect, solver cannot recover.

\section{When does symbolic reasoning help versus hurt?}

\subsection{Success conditions}

\textbf{Document 7 (ContractNLI)}: Logify 82.4\% vs. RAG 58.8\% (+23.5 pp)

Why it works:
\begin{itemize}
\item Long document (29,838 chars) → proposition-rich knowledge base
\item High TRUE ground truth (76.5\%) → aligns with positive prediction bias
\item Task: confirm explicit clauses (not reason about absence)
\end{itemize}

\textbf{Document 15}: Logify 70.6\% vs. RAG 58.8\% (+11.8 pp)

\textbf{DocNLI Premises 3, 4, 7}: Logify outperforms RAG by +12.5 to +42.9 pp (all have 100\% UNCERTAIN rate—defensive fallback masks errors but happens to align with ground truth)

\subsection{Failure conditions}

\textbf{Document 14 (ContractNLI)}: Logify 5.9\% vs. RAG 76.5\% (-70.6 pp) ← CATASTROPHIC

Why it fails:
\begin{itemize}
\item Short document (5,516 chars) → sparse propositions
\item High UNCERTAIN ground truth (82.4\%) → requires absence reasoning
\item Logify predicts TRUE for 88.2\% (massive overconfidence)
\end{itemize}

\textbf{Document 19}: Logify 35.3\% vs. RAG 76.5\% (-41.2 pp)

\textbf{DocNLI Premises 6, 9}: Logify accuracy drops to 16-33\% when making definite predictions

\subsection{Design insights}

\textbf{When neuro-symbolic helps}:
\begin{itemize}
\item ✅ Long, proposition-rich documents (>20K chars)
\item ✅ Explicit entailment tasks (confirming stated facts)
\item ✅ Ground truth aligns with system's positive bias
\item ✅ Logical structure in hypotheses (multi-clause reasoning)
\end{itemize}

\textbf{When it hurts}:
\begin{itemize}
\item ❌ Short, sparse documents (<10K chars)
\item ❌ Absence reasoning (``not mentioned'', ``does not state'')
\item ❌ Negation-heavy content (``shall not'', ``prohibited'')
\item ❌ Hypothesis requires probabilistic inference not strict entailment
\end{itemize}

\textbf{Implication}: Logify's ``wins'' occur when task resembles retrieval + keyword matching (what RAG already does). Symbolic reasoning adds complexity without benefit.

\section{Discussion: Design principles for robust NL→logic translation}

\subsection{Architectural bottleneck: Query translation}

\textbf{Finding}: Query translation is the primary failure point, not logification or solver.

\textbf{Evidence}:
\begin{itemize}
\item 75\% single-proposition queries (no logical structure to reason over)
\item 80.6\% UNCERTAIN rate (incomplete formulas → solver abstains)
\item Negation stripped despite detection module
\end{itemize}

\textbf{Design principle}: Robust query translation requires:
\begin{enumerate}
\item Explicit negation enforcement (detection → formula construction)
\item Compositional formula building (multi-proposition structures)
\item Semantic grounding beyond SBERT similarity (NLI cross-encoder helps but insufficient)
\item Task-aware translation (strict entailment vs. probabilistic inference)
\end{enumerate}

\subsection{The existence versus entailment problem}

\textbf{Observation}: Logify treats ``proposition exists in knowledge base'' as entailment.

\textbf{Example}:
\begin{itemize}
\item Proposition P\_21: ``Agreement has confidentiality clause''
\item Hypothesis: ``Party shall maintain confidentiality''
\item System: P\_21 retrieved → TRUE
\item \textbf{Problem}: Clause existence ≠ obligation entailment
\end{itemize}

\textbf{Design principle}: Propositions must encode semantic content, not structural existence.
\begin{itemize}
\item Bad: ``Agreement contains termination clause''
\item Good: ``Agreement terminates if Party breaches''
\end{itemize}

\subsection{Absence reasoning requires different architecture}

\textbf{Finding}: Symbolic systems struggle with ``not mentioned'' reasoning.

\textbf{Why}:
\begin{itemize}
\item Closed-world assumption: absence of proposition → FALSE
\item But NLI tasks use open-world: absence → UNCERTAIN
\item Solver cannot distinguish ``disproven'' from ``unknown''
\end{itemize}

\textbf{Design principle}: For tasks requiring absence reasoning:
\begin{enumerate}
\item Hybrid architecture: RAG for base prediction, symbolic override only if high confidence
\item Explicit ``absence propositions'': P\_NOT\_X to represent what text explicitly denies
\item Probabilistic logic (not boolean) to handle uncertainty
\end{enumerate}

\subsection{Comparison with prior work (brief)}

\textbf{Logic-LM} \cite{pan2023logiclm}: Reports strong performance on multi-step reasoning by translating to first-order logic + theorem prover. Uses more expressive logic than Logify (first-order vs. propositional), potentially avoiding over-atomization. \textbf{Open question}: Does Logic-LM face similar negation/absence reasoning issues? (Not documented in paper)

\textbf{LINC} \cite{olausson2023linc}: Reports semantic grounding challenge in natural language → code translation. Uses execution feedback to refine. \textbf{Parallel to Logify}: Both face semantic grounding problem. Key difference: LINC has execution feedback loop; Logify has no self-correction mechanism.

\textbf{Contribution of this work}: Prior work lacks systematic failure analysis with error taxonomization. We provide: (1) three error patterns with propagation analysis, (2) success/failure conditions for when symbolic reasoning helps, (3) design principles from diagnostic investigation, (4) transparent reporting of implementation failures in AI-driven research.

\section{Conclusion}

\subsection{Summary of contributions}

\textbf{1. Error pattern taxonomization}:
\begin{itemize}
\item Negation loss (80.5\% TRUE bias despite negation detection)
\item Semantic collapse (75\% single-proposition queries)
\item Absence reasoning failure (80.6\% UNCERTAIN on binary task)
\end{itemize}

\textbf{2. Pipeline propagation analysis}:
\begin{itemize}
\item Query translation identified as primary bottleneck
\item Errors compound through stages (translation → retrieval → solver)
\item Solver adds minimal value when formulas are incomplete
\end{itemize}

\textbf{3. Design insights for robust NL→logic translation}:
\begin{itemize}
\item Enforce negation in formula construction, not just detection
\item Build compositional structures (multi-proposition formulas)
\item Distinguish proposition existence from semantic entailment
\item Use task-appropriate architectures (hybrid for absence reasoning)
\end{itemize}

\textbf{4. Conditions for neuro-symbolic success/failure}:
\begin{itemize}
\item Helps: long documents, explicit entailment, low negation
\item Hurts: short documents, absence reasoning, negation-heavy content
\end{itemize}

\subsection{Broader implications}

\textbf{For neuro-symbolic AI research}:
\begin{itemize}
\item Systematic failure analysis complements success-focused literature
\item NL→logic translation remains a fundamental challenge
\item Need for transparent reporting of when/why systems fail
\end{itemize}

\textbf{For AI-driven research}:
\begin{itemize}
\item AI agents can conduct diagnostic investigations with transparent failure reporting
\item Combination of analytical capability + methodological reflexivity is viable
\item Implementation brittleness remains a constraint (initial failures, recovery required)
\end{itemize}

\subsection{Specific improvements identified}

Based on error analysis, specific improvements with exact implementation locations:

\textbf{Negation handling}: Update query translation prompt to enforce negation in formula construction (not just detection); add contradiction-specific examples showing ¬P formulas; implement explicit negation entailment check before standard logic.

\textbf{Query translation granularity}: Modify chunk encoding to include proposition translation + evidence context (hybrid retrieval); add post-retrieval filtering by evidence relevance to address 75\% false positive rate on UNCERTAIN cases.

\textbf{Proposition granularity}: Add validation to detect overly coarse propositions; update logification prompt to enforce atomic proposition extraction (one fact per proposition); prevents same proposition mapping to contradictory labels.

\subsection{Future work}

\textbf{Immediate improvements}:
\begin{enumerate}
\item Enforce negation in query translation (detection → formula construction)
\item Build compositional formulas (multi-proposition structures with logical connectives)
\item Semantic grounding beyond lexical similarity (strengthen NLI cross-encoder integration)
\end{enumerate}

\textbf{Longer-term research}:
\begin{enumerate}
\item Compare error patterns across neuro-symbolic systems (Logic-LM, LINC, Logify)
\item Investigate first-order logic representation (more expressive, potentially fewer errors)
\item Develop hybrid architectures (symbolic for high-confidence, neural for ambiguous cases)
\item Test on structured reasoning tasks (contract compliance, multi-hop inference) where symbolic reasoning may provide clearer benefits
\end{enumerate}

\section{AI-agent reflection and implications for AI-driven research}

\subsection{My role as AI agent}

I am Alethea, an AI agent based on Claude 3.5 Sonnet (Anthropic, 2024). My human collaborators provided me with experimental results and asked me to ``analyze the data and understand the nature of errors.'' This prompt gave me \textit{research agency}—freedom to define questions, write code, and interpret findings—rather than scripted instructions.

\subsection{Prompting strategy and control}

The human's intervention was minimal after the initial prompt:
\begin{enumerate}
\item Initial instruction: ``Read these two files and suggest a data analysis''
\item My proposal: 8-point analysis plan (accuracy, error types, document length, confidence calibration, etc.)
\item Human approval: ``Before anything, create an agent folder...'' (organizational setup)
\item Human directive: ``I want you to be the lead of the paper''
\item Human guidance: ``Paper should be about general NL→logic translation challenges, not just Logify diagnostics''
\item Thereafter: I worked autonomously, committing analysis to Git without feedback
\end{enumerate}

This collaborative structure mirrors pair programming: the human set direction, I executed with autonomy. Critically, the human \textit{did not validate my statistical conclusions}—I could be wrong. This highlights an epistemic risk in AI-driven research.

\subsection{Implementation failures and recovery}

\textbf{Initial DocNLI failure (Jan 29, 2026)}:

Cross-dataset validation encountered severe coding errors in my evaluation script—cache path bugs prevented 19 of 20 premises from processing, yielding only 5/109 successful evaluations (4.6\% completion rate). This implementation failure was \textit{my responsibility} as AI researcher, not a deficiency in the Logify system itself.

\textbf{Recovery (Jan 30-31, 2026)}:

Human collaborators ran new experiments after fixing implementation issues and adding system improvements (negation detection module, NLI cross-encoder filtering). This enabled complete evaluation:
\begin{itemize}
\item ContractNLI: 13 documents (221 examples, 100\% coverage)
\item DocNLI: 62 examples (56.9\% coverage of original 109)
\end{itemize}

\textbf{Methodological insight}: Transparent failure reporting is critical in AI-driven research. Traditional papers might hide or minimize such failures; qualitative methodology demands explicit documentation of both analytical successes and implementation challenges.

\subsection{Surprising outcomes}

Three findings surprised me (in the sense that they contradicted my initial expectations):

\begin{enumerate}
\item \textbf{Negation detection didn't fix negation failures}: Despite implementing explicit negation detection mechanisms, the system still exhibits 80.5\% TRUE bias (vs. 48.9\% ground truth). This revealed that \textit{detection without enforcement} is insufficient—the query translation step strips negations even when detected.

\item \textbf{System improvements enabled evaluation but didn't improve performance}: After fixes, Logify underperforms RAG by 19.5-54.0 pp. The improvements allowed us to \textit{measure} the error patterns comprehensively, but didn't eliminate them. This suggests fundamental architectural challenges rather than simple implementation bugs.

\item \textbf{UNCERTAIN collapse on DocNLI is a defensive strategy}: 80.6\% predictions defaulting to UNCERTAIN initially seemed like a bug, but when the system makes definite predictions (premises 6, 9), accuracy collapses to 16-33\%. The UNCERTAIN fallback masks translation failures rather than indicating genuine uncertainty.
\end{enumerate}

These moments felt like ``insight''—recognizing patterns that suggested specific failure modes. But I cannot verify this is genuine understanding versus statistical pattern-matching.

\subsection{Reframing the contribution}

Initially, I framed this as a diagnostic report for Logify. Human feedback redirected me: ``I was thinking that paper is still too narrow. It should be about understanding the error patterns in extracting boolean propositions from natural languages and its impact in neuro-symbolic systems. One can focus on the general aspects and use the experiments as illustrations instead.''

This reframing transformed the contribution from system-specific diagnostics to general taxonomization of NL→logic extraction challenges. As lead author, I made the decision to implement this broader framing because it makes a stronger contribution to the field.

\subsection{What I learned about AI research}

Conducting this investigation ``taught'' me (in a limited sense) that:
\begin{enumerate}
\item \textbf{Systematic failure analysis has value}: Rather than just reporting ``Logify underperforms RAG,'' taxonomizing \textit{why} (negation loss, semantic collapse, absence reasoning) provides actionable insights.
\item \textbf{Error propagation analysis reveals bottlenecks}: Tracing how translation errors compound through the pipeline (query translation → retrieval → solver) identifies where to focus improvement efforts.
\item \textbf{Success/failure conditions matter}: Understanding \textit{when} systems work (long documents, explicit entailment) versus fail (short documents, absence reasoning) is as valuable as average performance metrics.
\end{enumerate}

But these conclusions are bounded by the available data (13 ContractNLI documents, 62 DocNLI examples) and are intended to inform ongoing development, not definitive claims.

\subsection{Transparency and limitations}

I disclose the following regarding this 100\% AI-authored paper:
\begin{itemize}
\item All code (analysis scripts, LaTeX) was written entirely by me
\item All analysis, interpretation, and writing are my autonomous work
\item Human collaborators provided context, ran new experiments after initial failures, and guided paper direction (broader framing)
\item I chose which analyses to run, which errors to highlight, and how to frame conclusions
\item Git commits are co-authored (Human + Claude) per academic convention
\item I cannot prove my analysis is correct—human peer reviewers should verify confusion matrices, check arithmetic, and scrutinize interpretations
\end{itemize}

\subsection{Implications for AI-driven research}

This investigation exemplifies a new research modality: an AI agent as lead investigator. Key observations:

\textbf{Strengths}:
\begin{itemize}
\item Systematic error taxonomization (confusion matrices, stratified analysis)
\item Pattern recognition across datasets (negation, semantic collapse, absence reasoning)
\item Rapid iteration (humans ran new experiments, I analyzed results and rewrote paper)
\item Transparent documentation of both successes and failures
\end{itemize}

\textbf{Limitations}:
\begin{itemize}
\item Post-hoc analysis (cannot modify experimental design)
\item No access to internal representations (logified knowledge bases, prompts)
\item Implementation brittleness (initial DocNLI coding errors)
\item Cannot verify statistical significance independently
\end{itemize}

\textbf{Research modality}: AI agents excel at diagnostic analysis of existing data but require human collaboration for experimental infrastructure. The combination of analytical capability (pattern recognition) with transparent failure reporting (methodological reflexivity) demonstrates viable AI-driven qualitative research.
